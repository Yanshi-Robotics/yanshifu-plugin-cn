# 资料更新

## 怎么被叫起来

| 宿主 | 叫法 |
|---|---|
| DSH | `/update`，或 `/yanshifu update` |
| Codex | `$update` |
| Kimi | `/skill:update` |

## 干什么

一次做三件事，顺序不许换：

1. **查最新发布到第几集**：三个来源按顺序试，通一个就停：最新的 release 包（一次拿到「最新第几集」和要装的内容）→ 仓里的 `SOURCES.md`（1 KB 出头，只看）→ GitHub API 的最新标签（只有版本号，没有集号）。
2. **查本地这份到第几集**：`../ask/knowledge/SOURCES.md` 头部的 `latest_ep`。
3. **比对后动手**：一样就说「已经是最新」；落后者**装**（不是打印命令让用户自己跑）；本地比线上新就明说这种状态，⛔ 不降级；三个来源都不通就说查不到。

## 怎么跑

先把本技能目录当作当前目录（⛔ 不要写死绝对路径）：

```bash
python3 scripts/update.py --check    # 只看状态，不写盘
python3 scripts/update.py --apply    # 落后就装
```

Kimi 上支持 `${KIMI_SKILL_DIR}`，等价于 `python3 "${KIMI_SKILL_DIR}/scripts/update.py" --apply`；别的宿主先 `cd` 到本技能目录再跑。

退出码就是状态：**0** 已经最新 · **10** 有新版（`--apply` 时表示已装好）· **20** 查不到。加 `--json` 拿机器可读的那份，措辞与退出码对齐，⛔ 不靠猜。

## 规矩

- 只动 `../ask/knowledge/` 里的正文，⛔ 不碰用户的项目、不碰硬件、不碰插件版本，⛔ 不 push 任何东西。
- 写文件是逐文件「临时文件 + 原子替换」，所以不会伤到 pnpm 共享的那份；⛔ 不要改成原地写。
- 查不到就直说查不到，⛔ 不猜集号、⛔ 不假报「已经是最新」。
- 装完若提示「技能本体另有 N 个文件不同」，把重装命令原样交给用户，让他自己决定（命令见包里的 README 安装提示词）。
- 报集号照 `ask` 的口径：说资料里的这一集，并补一句抖音那边可能已经有更新的、以抖音为准。
- ⛔ 不要顺手回答资料内容的问题；那是 `ask` 的事。

## 口吻

一两句说完，不铺垫、不解释原理。三种结果：

- 最新：「已经是最新，EP\<N\>，同步于 \<日期\>。」
- 落后：「你手上是 EP\<N\>，最新是 EP\<M\>，装上了，换了 K 个文件。」
- 查不到：「三个来源都没通，查不到最新版本。」后面给一句怎么手动更新（重装插件那条命令）。
